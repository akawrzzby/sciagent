# 演示视频分镜脚本与操作指引

> 赛题要求：**5–8 分钟 / MP4 / ≥1080p / 普通话讲解，可配字幕**，内容须包含**项目介绍、核心功能演示、AI 技术亮点展示**。
>
> 本文给出逐镜头脚本：**时间轴 → 画面操作 → 讲解词 → 屏幕上应该出现什么**。
> 建议总时长 **7 分 10 秒**（含 10 秒片头留白），留出 50 秒安全余量给现场波动。

---

## 0. 录制前准备清单（务必提前 10 分钟完成）

### 0.1 环境准备

| 项 | 操作 | 验证方式 |
|---|---|---|
| 后端在线 | `ssh 179 'bash ~/sciagent/scripts/restart_backend.sh 9000'` | `curl http://127.0.0.1:9000/api/health` 返回 `status: ok` |
| 模型就位 | `~/models/bge-m3`、`~/models/bge-reranker-v2-m3` | `/api/health` 中 `dense_available: true`、`reranker_available: true` |
| 文献库已预热 | 至少上传 8 篇（含 Attention / BERT / GPT 系列 + 1 篇扫描件） | 文献库页面显示解析完成、章节数非 0 |
| 前端构建 | `cd frontend && npm run build` | `dist/` 生成，CSS 体积 > 30 KB（说明 Tailwind 生效） |
| 隧道在线 | `docker compose logs -f tunnel` | 拿到公网 HTTPS 地址，**在浏览器里先打开一次确认能访问** |
| 浏览器 | Chrome/Edge，**1920×1080**，缩放 100%，**关闭所有扩展**，深色模式关闭 | 截图检查 |

### 0.2 浏览器标签页布局（录制前就开好，别在录制中现开）

```
标签 1: 公网演示地址（正式演示用这个）
标签 2: 公网演示地址 /library（备用，万一主标签卡了直接切）
标签 3: 终端（准备展示一次 curl /api/health，30 秒即可，可选）
```

> **强烈建议**：不要在录制过程中上传大文件或下载 PDF。要展示"上传"就提前在文献库里放好；要展示"检索"就提前把推荐结果页预热好。

### 0.3 录屏设置

- 分辨率 **1920×1080**，帧率 30 fps（够用，不必 60）
- 格式 MP4 / H.264
- **不要**录制鼠标点击音效；鼠标指针保持可见
- 字体缩放：浏览器 100%，系统 100%（否则录制画面里的字会糊）

### 0.4 需要提前准备的数据快照

| 镜头 | 需要的真实数据 | 获取方式 |
|---|---|---|
| 3.2 | Attention 论文的 8 位作者 | 文献库打开该论文 → 阅读器 |
| 3.3 | 标题树含 `3.2.2 Multi-Head Attention` | 同上，左栏标题树展开到 3 级 |
| 3.4 | 扫描件 OCR 结果 | 库里放 `1706.03762v1_img.pdf`，解析完 → 阅读器 |
| 3.6 | 引用图谱（≥8 节点） | 文献库勾选 4–5 篇 → 图谱综述 |
| 3.7 | 基石节点指标 | 图谱页点最亮的节点 → 右侧指标面板 |
| 4.1 | 自动综述 / Future Work | 图谱页点对应按钮（先跑一次确认已生成） |
| 4.3 | arXiv 推荐结果 | 检索推荐页先点一次「刷新推荐」 |

## 2. 逐镜头脚本

### 镜头 1 · 片头（00:00–00:35）

**画面**：从浏览器地址栏开始（公网 HTTPS 地址可见），滚动到 SciAgent 界面，鼠标停在左侧导航上。

**讲解词**：

> 「大家好。我们是 SciAgent 团队，作品是**科研小助手**——一个面向文献阅读与写作的意图驱动型科研 Agent。
>
> 它不是聊天框套壳，而是一条**可溯源的科研流水线**：从 PDF 解析，到混合检索，到 Agent 自主取证与作答，再到引用图谱挖掘和论文写作辅助。
>
> 接下来七分钟，我会演示它的六个核心模块，并说明我们在 AI 架构上的几个关键设计。」

> **字幕建议**：片头大字标题「SciAgent · 科研小助手 —— 意图驱动的全流程科研助手」。

---

### 镜头 2 · 痛点（00:35–01:05）

**画面**：切到 PPT 或文档页（1 页即可），列出 4 条痛点。可用纯文字卡，不需要花哨动画。

**讲解词**：

> 「先说我们解决的问题。科研工作者读文献时有四组固定摩擦：
>
> **第一，PDF 不是文本。** 双栏、公式、图表、扫描件——粗暴复制出来是错序的。
>
> **第二，答案不敢信。** 大模型谈论文细节时会编造参考文献、张冠李戴作者。
>
> **第三，读过的文献攒不起来。** 阅读、翻译、提问、管理分散在四个工具里。
>
> **第四，不知道下一步做什么。** 读完二十篇论文说不清这个方向还剩哪些空白。」

---

### 镜头 3 · 系统总览（01:05–01:30）

**画面**：切回浏览器，用鼠标沿着左侧六个导航项依次划过（文献库 → 阅读器 → 智能问答 → 图谱综述 → 检索推荐 → 写作工作台），每个只停留 1 秒，让观众看清有六个工作台。

**讲解词**：

> 「SciAgent 有六个工作台，正好对应赛题的六大模块：文献库、阅读器、智能问答、图谱综述、检索推荐、写作工作台。
>
> 六个页面共享同一份文献库状态——你在文献库里勾选几篇论文，图谱、综述、Future Work 和写作的引用池会**立刻切换**到这一组。」

---

### 镜头 4 · 模块一：解析能力（01:30–02:10）⚠️ 高价值镜头

**画面**：
1. 切到**文献库**页，让观众看到论文列表（含「扫描件」和「已解析」状态标记）
2. 点开其中一篇 → 进入**阅读器**
3. 鼠标依次点：**左侧标题树** → 展开到 `3.2.2 Multi-Head Attention`
4. 切到**中文 / 双语**标签，展示对照双栏

**讲解词**：

> 「先看解析。
>
> 这是 Attention Is All You Need。我们没有用现成的 PDF 解析库直接抽字符串，而是做了**版式感知**的解析：词级坐标 → 双栏聚类 → 栏序还原，这样双栏论文的正文才是正确顺序的。
>
> 标题树是三路证据联合判定的：**显式编号**、**规范章节名**、**排版特征**。同时有一组负向规则专门排除误判——比如论文左边那个竖排的 arXiv 戳记，我们早期版本就把它误判成标题，现在已经修掉了。
>
> 这里点开 3.2.2，页面直接定位过去。」

> **⚠️ 关键提示**：如果时间紧，标题树那一跳**必须保留**——它一句话说清了"结构化解析"和"拍平字符串"的区别。

---

### 镜头 5 · 模块一（续）：作者与扫描件（02:10–02:35）

**画面**：切到文献库详情或元数据面板，展示作者列表高亮第 6 位作者；然后打开**扫描件**那篇论文，展示它同样有完整的标题、章节和正文。

**讲解词**：

> 「作者我们做到了八位全对，包括第六位 Aidan N. Gomez——他当时在多伦多大学。这个字段可以直接回答赛题里的第一个测试问题。
>
> 右下角这篇是**纯扫描件**，一个字符的文本层都没有。我们的处理方式不是上 OCR 引擎——OCR 引擎会毁掉双栏顺序和公式——而是**用多模态大模型逐页转写**：渲染成图片，模型读出结构化 Markdown，再从 Markdown 重建标题树、作者、摘要和参考文献。十五页大约三分钟。」

---

### 镜头 6 · 模块二：Agent 问答（02:35–03:25）⚠️ 最高价值镜头

**画面**：
1. 切到**智能问答**页
2. 点击预置问题「论文 Attention Is All You Need 的第 6 作者是谁，在哪个机构工作？」
3. **慢速播放**（在"思考过程"面板展开时暂停 2–3 秒）
4. 让 token 级流式输出跑完
5. 鼠标悬停/点击下方的**证据来源卡片**

**讲解词**：

> 「这是核心。提问之后，Agent 会先把任务拆解成 DAG，再逐个调用工具取证。
>
> 请注意这个**思考过程面板**：它不是模型的自由发挥，而是我们把每一次工具调用都结构化地暴露出来——调了哪个工具、传了什么参数、返回了什么。用户可以逐条审计。
>
> 我们的 Agent 架构是**两阶段**的：先把证据取回来，形成一个带页码、带字符区间的结构化证据列表；再让模型**只依据这些证据**作答。这个拆分的直接好处是——工具调用失败不会浪费已经写了一半的正文，而且前端能明确区分"还在检索"和"正在写答案"。
>
> 答案下面每一个引用都可以点。点进去会跳到阅读器的对应位置，精确到字符区间。」

> **⚠️ 关键提示**：一定要**展示思考过程面板**。这是「Agent 思考过程可视化」评分点的直接证据，别只展示答案。

### 镜头 7 · 模块二（续）：抗幻觉（03:25–03:50）

**画面**：切到写作工作台的「论文框架」标签（**先提前生成好**），滚动到「参考文献」区域，让观众看到"✓ 已校验"与被拦截的条目。

**讲解词**：

> 「抗幻觉我们做了五层纵深防护，不是一层。
>
> 第一层**证据绑定**：答案里的引用编号必须落在检索到的证据集合内，超出的直接删除，并在界面上明确告诉你"移除了 N 个无据引用"。
>
> 第二层**引用真实性校验**：模型生成的每一条参考文献，都要跟文献库里的真实文献做标题模糊匹配、arXiv ID 和 DOI 精确匹配。对不上的，**不会静默丢弃，而是单独列出来告诉你系统替你拦下了哪几条错引**。
>
> 第三层提示注入隔离，第四层结构化输出校验，第五层无据拒答——证据不足时它会明确说"提供的文献中没有找到能支撑该问题的证据"，而不是编一个答案给你。」

---

### 镜头 8 · 模块三：中英联动（03:50–04:10）

**画面**：阅读器的**双语**标签，**用鼠标滚动右侧对照栏**，让观众看到左右两栏同步移动。

**讲解词**：

> 「阅读器这一块，我们做的是**中英双向联动**。注意这里的对齐方式：翻译不是逐段独立生成的，而是先产出一份左右一一对应的 segment 列表，再用同一份列表渲染双栏、按比例同步滚动。所以段落永远严格对应，不会出现左边第三段对右边第五段这种错位。
>
> 另外正文里的引用标记和参考文献条目是**双向可跳转**的。」

---

### 镜头 9 · 模块五：引用图谱（04:10–04:55）⚠️ 高价值镜头

**画面**：
1. 切到**图谱综述**页
2. 鼠标在图上缓慢画一个圈（展示力导向布局与节点大小）
3. **点击最亮（琥珀色）的节点** → 右侧出现指标面板
4. 滚动右侧表格

**讲解词**：

> 「把文献之间的引用关系建成图之后，我们不只看被引次数。
>
> 我们同时算了**四个指标**：PageRank 衡量影响力，Betweenness 衡量桥接作用——一篇论文如果处在知识流的咽喉位置，引用量可能不高但枢纽度很高；k-core 衡量核心团的凝聚厚度；HITS 区分枢纽与权威。
>
> **综合四个指标**才能判定谁是基石。节点颜色就是角色：琥珀色是基石，深蓝是核心，青色是衍生。节点大小正比于 PageRank。
>
> 点开这个节点，右侧是它的完整指标——被审稿人追问"为什么它是基石"的时候，这一屏就是答案。」

---

### 镜头 10 · 模块五（续）：自动综述与 Future Work（04:55–05:35）

**画面**：切到「自动综述」标签 → 滚动核心发现与开放问题；再切到「Future Work」标签 → 展示一个研究机会卡片。

**讲解词**：

> 「基于同一张图，系统能自动生成综述：它会区分基石文献和衍生文献，并且说明**为什么**某篇是基石——依据就是刚才那些图指标加上摘要。
>
> Future Work 这一块我们不想只是摘抄。我们的做法是定位每篇论文的 Future Work、Limitations、Discussion 片段，去重之后，归纳成**可执行的研究机会**，每个机会都带新颖性论证、难度和影响力评估，还标出它来自哪几篇论文。
>
> 也就是说，把"别人说要做什么"变成"你可以做什么"。」

### 镜头 11 · 模块六：写作工作台（05:35–06:05）

**画面**：
1. 「架构图」标签 → 选择 Mermaid → 展示实时渲染预览（**提前生成好**）
2. 「图表 & Caption」标签 → 展示生成的图表 + Figure Caption

**讲解词**：

> 「写作工作台有三个能力。
>

> 第三个是 **CSV 到学术图表**：粘贴论文里的数据表，直接得到出版级的图、Figure Caption、关键结论和 Markdown 数据表——写作里最机械的一环，一次操作就完成了。」

**画面**：回到系统主界面（文献库或问答页），缓慢后退，让观众看到完整界面。

**讲解词**：

> 「总结一下。SciAgent 的核心主张是三条：

## 3. 录制技巧

### 3.1 节奏

- **每个镜头之间留 0.5–1 秒停顿**，剪辑时能看清切换点
- 讲词比画面**提前 0.5 秒**起，念起来不赶
- 语速控制在 **每分钟 240–280 字**（比日常讲话慢一点，评委要听清术语）

### 3.2 鼠标

- 关键操作**放慢**，一次只做一件事
- 讲到"点开这个节点"时，**先说再点**，说完停 1 秒让画面跟上
- 不要来回抖动鼠标

### 3.3 剪辑

| 保留 | 删掉 |
|---|---|
| 演示动作 | 加载等待（超过 2 秒的转圈） |
| 思考过程面板 | 无意义的滚动 |
| 图表与指标 | 鼠标在页面上乱晃的片段 |

> **建议**：只在段落之间剪，不要剪掉"思考过程"这类**有信息量的等待**——那正是 Agent 在工作的证据。

### 3.4 字幕

- 烧录字幕，字体 40–48 pt，白字 + 2px 黑描边，底部居中
- 关键词（模块名、技术名）用**另一种颜色**（如琥珀色）标出
- 字幕**不遮底部操作区**，如果画面下方有内容就放顶部

## 4. 常见事故预案

| 事故 | 预案 |
|---|---|
| 公网地址打不开 | 切备用标签页；若都不行，切到**本地演示**（`http://localhost:8080`）继续，并在片中不提地址 |
| 流式输出卡住 | 换一个**提前问过**的问题（问答页保留历史会话，点历史记录即可重看，不会重新消耗时间） |
| 图谱加载慢 | 提前点过一次，图会缓存；实在不行跳过图谱，直接讲图指标截图 |
| OCR 那篇没解析完 | **不要等**——跳过扫描件镜头，用一句话带过：「扫描件走多模态逐页转写，我们实测十五页约三分钟」，不要在录制中等待 |
| 大 PDF 上传失败 | 录制中**不要上传**；提前放好，镜头里只展示已上传的结果 |
| 时间超了 | 优先砍：镜头 8（中英联动，缩到 15 秒）、镜头 12（检索推荐，并入镜头 11 的一句话） |
